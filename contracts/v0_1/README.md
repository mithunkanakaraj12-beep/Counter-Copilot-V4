# Data contract v0.1 (revised proposal)

Interface definitions, deterministic reference functions and checks. No server, database,
worker or frontend is implemented here. Nothing is approved or frozen.
Rules are in [docs/DATA_CONTRACT.md](../../docs/DATA_CONTRACT.md).

| Path | Contents |
|---|---|
| `models.py` | Pydantic models: API payloads, storage shapes, model output, grounded result |
| `api.py` | Operation list used for generation |
| `openapi.yaml`, `extraction-proposal.schema.json` | Generated by `generate_openapi.py`. Do not edit |
| `reference/` | Pure parsing, grounding and comparison functions with versioned word lists |
| `examples/` | Synthetic payloads, generated by `build_examples.py` from `fixtures/` |
| `benchmark/` | Gemini's 30 cases: labels as written, emails, schema expression, results |
| `qa/matrix.json` | The 57 QA tests and what the contract covers of each |
| `oas-3.1/`, `validate_openapi.py` | Official OpenAPI 3.1 schemas and the offline validator |
| `typescript/` | Type generation from `openapi.yaml` and compile-time consumer checks |
| `test_*.py` | Contract and reference-function checks, not application tests |

## Run the checks

From the repository root, with Python 3.13:

```
python -m pip install -r contracts/v0_1/requirements.txt
python contracts/v0_1/generate_openapi.py --check
python contracts/v0_1/build_examples.py --check
python contracts/v0_1/build_benchmark.py --check
python -m pytest contracts/v0_1
python contracts/v0_1/validate_openapi.py
```

Run the generators without `--check` after changing models, fixtures or the benchmark mapping.

TypeScript, with Node 22 (needs the npm registry):

```
cd contracts/v0_1/typescript
npm install --ignore-scripts
npm run generate
npm run check
```

The generator and compiler versions are pinned; their own dependencies are not, because no
lockfile is committed yet.

CI (`.github/workflows/contract.yml`) runs all of the above and a second validator,
`openapi-spec-validator`. A workflow does not protect a branch by itself: the repository
owner must make `contract-python` and `contract-typescript` required checks.

## What passing does not show

- No application behaviour: authorization, transactions, locking, idempotency and auditing
  are requirements without code or tests.
- No model accuracy: no model has been run against the benchmark.
- Frontend compatibility: the TypeScript checks are written from the requirements, not
  compiled against frontend code.
